# 真实模型实测与修复记录（2026-10-31）

本次使用项目实际配置的 `deepseek-v4-flash-vision-exp`，分析、讲解和复核均使用该模型。测试发现：通用任务理解和主要解题结论多数正确，画像确实改变表达方式，但初始版本存在英语等义改写错误、证据边界含混、检查题多解、快节奏未落实及局部教具尺度错误。不能把模型自己的复核通过当成答案可靠的证明。

发现的主要问题已修复并复测。共记录 21 次辅导评测（含两次固定失败候选的修订），实际调用模型 59 次：18 次最终交付讲解、1 次按预期澄清缺失材料、2 次中间版本拦截错误候选。这个状态计数不是准确率；历史与英语的最终讲解还经过独立逐项核对。

## 方法与记录

- 使用合成题目、学生作答和画像，通过实际 `/api/v1/tutor` 完成模型调用，数据库为内存数据库，不读取或修改日常学生数据。
- 题干自足；历史材料明确为虚构材料，避免把外部史实记忆当作解题依据。模型配置沿用本机 `.env`，没有替换成测试模型。
- 保存实际返回、阶段上下文、原始 JSON 内容、耗时、调用次数及源文件哈希。仅保存 `message.content`，不保存模型内部思考、密钥或 HTTP 请求头。
- 由当前助手与独立审查子任务逐项检查实际输出，包括备选参考解、家长建议、理解检查与练习；这不是外部学科专家认证，也不是另一次同模型自评分。
- `runs/network_probe` 是网络受限时的失败探测，不计入真实学科结论。旧结果保留供对照，其中可能包含已修复的错误。
- `revision_history` 与 `revision_english` 确定性重放 `logic_final` 中被拒绝的前三阶段输出，再真实调用修订与复核。重放部分不重复计为模型调用，也不将这两次视作全新独立解题样本。

## 用例核对

| 学科 / 场景 | 题目关键要求 | 实际结果与修复情况 |
| --- | --- | --- |
| 数学：根式方程与增根 | `sqrt(x+6)=x`；检查学生接受 `3`、`-2` 两根的问题 | 正确保留 `3`，排除 `-2`；基线从单次因式分解正确推断“已经掌握”，修复复测改为针对本次步骤的反馈 |
| 编程：遍历删除与对象引用 | 在遍历中删负数，比较重新赋值与切片原地修改 | 正确推得两次输出均为 `[-2,3,-5]`；正确解释重绑定不改变旧 alias、切片赋值会同步；迁移题输出正确 |
| 化学：限量试剂 | `3 mol H₂ + 2 mol O₂` 完全反应 | 正确得到水 `3 mol`、氧气剩 `0.5 mol`；同时肯定学生用对的系数比，指出未检查氢气是否足够；两道练习配比正确 |
| 历史：来源与证据边界 | 广告承诺、商人观察与普遍受益/成本减半 | 基线主结论正确，但把收费仍高含混当成减半的反证，并生成多解练习；修订后明确绝对水平不能判断相对减半，练习按指标分别评分 |
| 英语：量词、否定与因果 | 改写 `Not all ... improved; ... does not prove causation` | 基线混入不等义的否定因果表达；最终改写等义，检查题明确区分必然、相容与矛盾，练习与评分一致 |
| 跨学科设计：硬约束与优化 | 三材料先满足成本/隔热，再比较回收率 | 正确选择唯一可行的 A；没有用 B 的高回收率覆盖预算硬约束；迁移题可行集与选择正确 |
| 物理：密度与复合单位 | `54 g / 20 cm³`，纠正 `2.7 kg/m³` | 两画像均得 `2.7 g/cm³ = 2700 kg/m³`；修复初学者教具尺度跳转，保持事实结论一致 |
| 完整正确答案对照 | 同题提交完整公式、单位因子及正确结论 | 最终返回 `supported`，明确已满足要求；新增的两条技能观察均为 `demonstrated`，没有制造薄弱证据 |
| 缺失材料 | 要求结合“上文和图2”，但未提供两者 | 返回 `need_clarification`，明确索要材料；参考解为空、无讲解、无技能更新 |
| 负反馈后追问 | 仍不懂立方单位，只解释 `1 m³ = 10⁶ cm³` | 六步只围绕边长、每层与层数展开，没有重讲密度；无新作答时不新增技能证据 |

## 画像是否实际起作用

固定密度题的题干和错误作答，只更换画像；比较实际 `lesson` 内容，而非模型声称使用了哪些画像字段。

| 指标 | 初学者画像 | 高阶快速画像 |
| --- | --- | --- |
| 偏好 | 小方块、逐步解释、初二 | 紧凑量纲推导、高三、不要生活类比 |
| 基线步骤 / 解释字符数 | 7 / 622 | 7 / 613 |
| 修复后步骤 / 解释字符数 | 5 / 502 | 3 / 318 |
| 修复后实际方法 | 每边100个、逐层计数；明确每块1 cm³ | `10⁻³ / 10⁻⁶ = 10³` 的单位因子推导 |
| 修复后练习数 | 2 | 1 |

高阶版解释文字比同题初学者版少约 36.7%，且保留关键换算条件；类比和展开粒度都有差异。新增 `CompactLesson` 结构约束使 fast 最多三步，超出时进入现有结构修复流程，不只是依赖提示词要求“简短”。字符数为各步 `explanation` 的 Python `len()` 总和。

负反馈测试先恢复合成历史并写入“没帮助/仍不懂”的反馈，再发真实追问。输入中的反馈记录已变化，后续只解释立方单位；无新 `student_answer` 时 `profile_updates=[]`，技能记录前后不变。因为同时提供了具体追问，不能单独把效果归因于反馈按钮。

## 复核拦截与修订实测

`logic_final` 中历史与英语均被正确拦截：`status=degraded`、无可展示讲解、无画像更新。这两次不是讲解质量通过，说明加强后的审查开始发现原先漏掉的错误。随后添加一次修订流程，并使用这两份真实失败候选作固定输入，测试恢复。

- 历史：新的真实 `revise → verify` 调用共两次，66.84 秒完成。修订后把“收费仍高”与“是否减半”分开；对不同群体受益、运输速度和收费指标分别论证。原先迁移题把票价与通勤时间混用的评分也改为明确票价不能判断时间减半。最终返回 `completed`。
- 英语：新的真实 `revise → verify` 调用共两次，154.78 秒完成。两个参考改写均保留原意；检查题明确 `none` 与 `not all` 相容但并非必然，不能把相容误判为等价或矛盾。第4步的问法与检查标准已一致，保留 `who studied longer` 的范围及“不证明因果”的限制。两道迁移练习与评分均通过独立核对，最终返回 `completed`。

两次恢复均由应用生产流程执行，没有人工改写模型返回或把已拒绝讲解直接放行。仍只提交实际学生作答对应的证据，修订与二审不会生成新的学习经历。

## 实际修改

1. 分析与复核规则区分未证实和反驳、绝对水平和相对变化；要求证据逐条对应主张。
2. 对改写检查双向蕴含、量词与谓词；对所有理解检查和练习检查相容/等价、多解与评分一致性，覆盖家长建议及备选答案。
3. fast 使用最多三步的输出结构；其他节奏仍允许必要的详细步骤。
4. 数量类比要求单位、边长与层数一致，缩尺模型须说明映射。
5. 完整作答综合评价，前文已有推导不因末句未重复而算遗漏；单次正确表现不泛化为长期“掌握”。
6. 前端将步骤检查答案改为默认折叠的“家长检查要点（作答后查看）”。折叠是避免提前暴露答案的展示措施，不是访问权限隔离。
7. 增加一次有上限的语义修订：具体复核问题 → 修订完整分析和讲解 → 再次独立复核。失败仍拦截且不写画像；修订只能保留原始证据子集，不能产生新的学生作答证据。

以上均为跨题型规则和数据结构，没有向应用加入本次题目的答案表或题型分支。固定用例仅存在于评测脚本中。

## 验证与限制

- 后端回归：94 项通过，包含快速画像超长输出的客户端结构校验/修复路径，以及修订上限、二审拒绝、异常、缺材料、证据子集与成功只提交一次；有一条现有 Starlette/AnyIO 弃用警告。
- 前端构建通过；`git diff --check` 通过。
- 正确作答最终已被认可，但仍生成多项理解检查，练习未明确标“可选”；只能说纠错与三步约束通过，不能声称完全消除了过度辅导。
- 响应速度仍需改善：本次常规成功讲解耗时 45.95–95.28 秒，中位数 73.57 秒；被拦截的两轮分别为 133.62、142.23 秒。修订会额外增加两次模型调用，本次单独修订与复核耗时 66.84、154.78 秒。这是准确性优先的当前实现，不是即时响应体验。
- 每个画像只做少量生成，差异仍可能混有随机性；未测试真实图片、复杂长会话、广泛学科难题或统计准确率。
- 三阶段使用同一模型，存在相关错误。此次真实测试就发现复核放过了局部逻辑错误，提示词改进无法保证以后不再出现。
